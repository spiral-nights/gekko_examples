# `wit_greeter` Example

A minimal WebAssembly Component Model (WIT / WASI Preview 2) component implemented in Gleam and compiled via MoonBit + `wit-bindgen` + `wasm-tools`.

## What It Demonstrates

- **WIT Contract (`wit/world.wit`):** Defines `package demo:greeter@0.1.0` with `world greeter`.
- **Host Import:** Imports `logger.log(msg: string)` and calls it from Gleam via `src/wit/logger.gleam`.
- **Exported Interface & Record:** Exports `api.greet(u: user) -> string`, passing a WIT `record` (`User`) with an `option<string>` field across the Canonical ABI boundary.

## Project Layout

```text
wit_greeter/
├── gleam.toml                 # Declares gleam_stdlib dependency
├── wit/
│   └── world.wit              # WIT interfaces (`logger`, `api`) and `world greeter`
└── src/
    ├── wit/                   # AUTO-GENERATED by `gekko wit gen` (do not edit manually)
    │   ├── api_types.gleam    # `User`
    │   └── logger.gleam       # `@external(moonbit, ...)` stub calling host `logger.log`
    └── api.gleam              # Starter export stub generated once, then implemented by hand
```

## How It Was Created

1. **Defined the WIT schema:** Wrote `wit/world.wit` specifying `logger`, `api`, and `world greeter`.
2. **Generated Gleam bindings and export stubs:** Ran `gekko wit gen`:
   ```bash
   gekko wit gen
   ```
   - Files under `src/wit/` are regenerated automatically whenever `gekko wit gen` is re-run.
   - `src/api.gleam` is created once and preserved on subsequent `gekko wit gen` runs.
3. **Implemented export:** Filled in `greet` inside `src/api.gleam`.

## How to Check & Build the Component

Ensure `wit-bindgen`, `wasm-tools`, and Gleam dependencies (`gleam deps download`) are available:

```bash
cd wit_greeter

# Type-check the bridged MoonBit + wit-bindgen workspace
gekko wit check

# Compile core Wasm and bundle the WASI Preview 2 component (.wasm)
gekko wit build --output dist/greeter.wasm
```

Inspect the resulting component interface with:

```bash
wasm-tools component wit dist/greeter.wasm
```
