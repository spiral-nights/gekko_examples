# `file_io` Example

Reads and writes files from Gleam using the third-party [`moonbitlang/x`](https://mooncakes.io/docs/moonbitlang/x) (`moonbitlang/x/fs`) package configured via `moonbit/moon.mod` and bound automatically with `gekko moonbit bind`.

## What It Demonstrates

- **Third-party MoonBit dependencies (`moonbit/moon.mod`):** Uses MoonBit's native manifest format (`import { "moonbitlang/x@0.5.7", }`), which `gekko` emits into the generated workspace's `moon.mod`.
- **Automated binding & adapter generation (`gekko moonbit bind`):** Generates both:
  - `src/ffi/fs.gleam` — Clean Gleam module importing `gleam/option.{type Option}` with idiomatic Gleam types (`Result(..., String)`, `BitArray`, `List(String)`, `Option(String)`).
  - `moonbit/fs_adapter/` — MoonBit adapter package converting `raise IOError -> Result[_, String]` (via `Error::to_string(__err)`), `Bytes <-> @gprelude.BitArray`, `ArrayView[String] <-> @gprelude.GList[String]`, and optional parameters (`encoding? : String <-> String?`), while calling zero-conversion functions like `path_exists` directly against `moonbitlang/x/fs`.
- **File I/O operations (`src/file_io.gleam`):** Checks `sample.txt` (`path_exists`, `is_file`), reads its text and raw bytes (`read_file_to_string`, `read_file_to_bytes`), performs a write/read/delete round-trip (`write_string_to_file`, `remove_file`), and verifies error handling on missing files.

## Project Layout

```text

├── sample.txt                         # Sample input file read by `main`
├── moonbit/
│   ├── moon.mod                       # Native MoonBit manifest declaring `"moonbitlang/x@0.5.7"`
│   └── fs_adapter/                    # GENERATED by `gekko moonbit bind moonbitlang/x/fs`
│       ├── fs_adapter.mbt
│       └── moon.pkg
└── src/
    ├── ffi/
    │   └── fs.gleam                   # GENERATED by `gekko moonbit bind moonbitlang/x/fs`
    └── file_io.gleam                  # Gleam application reading/writing files via `ffi/fs`
```

## How It Was Created

1. **Configured dependencies:** Created `gleam.toml` (`gleam_stdlib`) and `moonbit/moon.mod` (which can be edited by hand or managed with `moon -C moonbit add moonbitlang/x`):
   ```moonbit
   name = "file_io"
   version = "0.1.0"

   import {
     "moonbitlang/x@0.5.7",
   }
   ```
2. **Generated the `moonbitlang/x/fs` bindings and adapter:** Ran `gekko moonbit bind` to inspect `moonbitlang/x/fs`'s `.mbti` interface and generate `src/ffi/fs.gleam` plus `moonbit/fs_adapter/`:
   ```bash
   gekko moonbit bind moonbitlang/x/fs --root file_io
   ```
   - `path_exists(String) -> Bool` requires no conversions and binds directly to `"moonbitlang/x/fs"`.
   - Functions that raise `IOError`, accept `encoding? : String`, or use `Bytes` / `ArrayView[String]` bind through `moonbit/fs_adapter`.
3. **Wrote application logic:** Created `src/file_io.gleam` importing `ffi/fs` (`import ffi/fs`) to read `sample.txt` and exercise file round-tripping and missing-file `Error` handling.

## How to Run

First download Hex dependencies if `build/packages/` is not already populated:

```bash
cd file_io
gleam deps download
cd ../..
```

Next transpile and check the MoonBit workspace, copy `sample.txt` into the generated workspace directory so the Wasm/JS process sees it in its working directory, and run:

```bash
# Type-check the transpiled MoonBit workspace (generates file_io/build/moonbit/)
gekko check --root file_io

# Stage the input file in the MoonBit workspace cwd
cp file_io/sample.txt file_io/build/moonbit/sample.txt

# Run on Wasm or JS
gekko run --root file_io --target wasm
gekko run --root file_io --target js
```
