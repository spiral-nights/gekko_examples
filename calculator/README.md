# `calculator` Example

A command-line mathematical expression and mini-script calculator written in Gleam using the pure-Gleam [`party`](https://hex.pm/packages/party) parser combinator library from Hex.

## What It Does

`calculator` reads mathematical expressions, variable definitions, and user-defined function definitions, parses them with a recursive-descent parser built from `party` combinators, and evaluates them sequentially:

- **Stateful execution across statements:** Variable bindings (`let`) and function definitions (`fn`) persist from one statement to the next, whether passed as multiple command-line arguments, separated by `;`, or evaluated in the built-in showcase script.
- **Structured error reporting:** Syntax errors include line and column positions from `party`; runtime errors clearly report undefined variables/functions, arity mismatches, domain violations (e.g., `sqrt(-4)`, `ln(0)`), and division by zero.
- **No external runtime required:** Core parsing and evaluation are 100% pure Gleam (`gleam_stdlib` + `party`). `moonbitlang/core/env` is bound via `gekko moonbit bind` solely to read CLI arguments (`env.args()`).

## Supported Syntax & Built-in Functions

| Category | Syntax / Names | Notes |
| --- | --- | --- |
| **Operators** | `+`, `-`, `*`, `/`, `%`, `^`, unary `+`/`-`, `(...)` | Standard precedence (`^` is right-associative, e.g. `2 ^ 3 ^ 2 == 512`, `2 ^ -3 == 0.125`) |
| **Constants** | `pi`, `e`, `tau` | Pre-populated in the default environment |
| **Variables** | `let <name> = <expr>` | Binds or updates a variable for subsequent statements |
| **User functions** | `fn <name>(<p1>, <p2>, ...) = <expr>` | Evaluates parameters in a local scope with arity checking |
| **1-arg built-ins** | `sqrt`, `abs`, `floor`, `ceil`, `round`, `ln`, `exp` | Mathematical functions (`sqrt` requires `x >= 0`, `ln` requires `x > 0`) |
| **2-arg built-ins** | `min(a, b)`, `max(a, b)`, `pow(a, b)` | Binary helpers |
| **3-arg built-in** | `clamp(x, min, max)` | Clamps `x` to `[min, max]` (`min <= max` required) |
| **Variadic built-ins** | `sum(a, b, ...)`, `avg(a, b, ...)` | Require at least one argument |

## How to Build & Run from the Command Line

First download dependencies if `build/packages/` is not already populated:

```bash
cd calculator
gleam deps download
```

### 1. Build a native executable and pass expressions on the command line

```bash
gekko build --target native
```

Evaluate a single expression:

```bash
./calculator.exe "2 + 3 * 4 ^ 2"
# 2 + 3 * 4 ^ 2  =>  = 50.0
```

Pass multiple statements (defining functions, binding variables, and calling them):

```bash
./calculator.exe "fn hypot(a, b) = sqrt(a^2 + b^2)" "let c = hypot(3, 4)" "c * 10"
# fn hypot(a, b) = sqrt(a^2 + b^2)  =>  defined hypot/2
# let c = hypot(3, 4)  =>  c = 5.0
# c * 10  =>  = 50.0
```

Or separate statements with `;` in a single argument:

```bash
./calculator.exe "let r = 5; round(pi * r^2)"
# let r = 5  =>  r = 5.0
# round(pi * r^2)  =>  = 79.0
```

Error reporting for runtime and syntax errors:

```bash
./calculator.exe "10 / (5 - 5)" "1 + * 2"
# 10 / (5 - 5)  =>  ERROR: Division by zero
# 1 + * 2  =>  ERROR: Syntax error at line 1, col 3: unexpected token '+'
```

### 2. Run the built-in showcase script (no CLI arguments)

Running `./calculator.exe` with no arguments (or via `gekko run`) executes the built-in multi-statement demonstration:

```bash
gekko check
gekko run --target native
gekko run --target wasm
gekko run --target js
```

Output:

```text

```

### 3. Run the unit tests

```bash
gekko test --target wasm
```
